| 分组 | 数量 | 内容 |
| --- | ---: | --- |
| 主题 topic | 36 | 原有亲属、饮食、交通、学习、家具等专题；新增性质与状态、动作与变化、概念与关系、语法与功能词、物品与材料，保留 Others |
| 用途／语体 usage | 3 | 日常口语、书面表达、文言 |
| 词语类型 form | 14 | 名词、动词、形容词、副词、数词与量词、代词、虚词、拟声与感叹、词组与句式、语素与构词、缩略语、符号与标记、成语、惯用语与谚语 |

同组内取并集，不同组取交集；未选择的组不增加限制。例如“家具＋电器”再加“日常口语”，表示家具或电器中适合日常交流的词。词性也遵循同一规则：同时选名词、动词表示两者任一，而不是要求条目同时具备两种词性。

Study 的筛选与匹配／已学数量限定当前 Stage；词库筛选页使用全库标签计数，应用后与词库页的难度、搜索、学习状态和收藏条件组合。两处选择各自独立。预览和取消不修改学习计划。

## 标注依据与边界

- 全量检查当前教学释义和词性。自动规则读取释义及词性；显式编辑以完整汉语词的所选义项为准，不用例句关键词、单字子串或 Stage 随意联想主题。英文模板句首 Describes 不作为“交流”证据，真实的 to describe 仍保留表达义。
- 词语类型直接来自词性证据。多词性词条允许多个类型标签；专名、名词性词组归名词，动词性词组同时可归动词和词组。单字不会仅因字数少就被判成语、缩略语或黏着语素。
- 新词词性修订结合有限精确词表、教学义的语法信号和现有 jieba 词典的明确词性；人名／地名标记与单字含义冲突时另行按当前教学义修订，不能把所有新增词一律当名词。词性来源辅助判断不等于权威词典或人工认证，原义与修订证据保存在 `tools/vocabulary_v2/` 的编辑记录中。
- 新增的中性主题只补已有目录的语义空缺。没有更具体主题依据的形容词可归性质与状态，一般动词义可归动作与变化；名词不能只凭词性归“概念与关系”或“物品与材料”，仍需对应释义证据。
- 日常口语包括“家人、冰箱”等中性日用词。用途／语体只依据明确常用词表或用法标记，不把所有词默认标成口语、书面或文言，也不以罕度代替语体。
- 历史是题材，文言是用法。古代首饰、古官职不自动成为文言；现代谈论古籍的词也不会仅因所指年代久远就标文言。
- 成语依据明确 `idiom` 词性及已有例外，不依四字长度推定。固定表达与普通词组保留区别。
- `topic_others`（Others／其他）表示尚无主题、用途或类型正式标注，只单独出现。补上任一正式标签即移除 Others；有可靠词性但尚无具体主题的词不算 Others。未匹配内置来源的用户导入词仍由运行时归 Others。

已有同形词边界规则继续保留：drive away 不按驾驶归交通，wind 的弯曲义不按风归天气，sea bream 不拆 sea 归天气；table salt、periodic table 不归家具，spring 的泉水／弹簧／春卷义不按季节归时间；temple 的解剖义不归宗教。明确的稳定ID例外只在原词头仍匹配时优先；替换后的新头重新分类。运行时同时校验来源ID与实际词头，旧库暂缓刷新时不借用新词标签。

## 维护与验证

维护入口为 [build_word_tags.py](../tools/build_word_tags.py)。输入词数与哈希从 [词库快照](wordlist-validation.json) 读取，不再写死旧 13,223 词或旧哈希。正式词库和快照经审核后，依次执行：

```powershell
python tools/build_word_tags.py --write
python tools/build_word_tags.py --check
```

两条命令已针对当前 20,000 词快照实际执行通过。`--write` 只生成标签目录、正式映射、样本、统计、全量理由表和主题待审清单；`--check` 只读核对快照哈希／词数、稳定 ID、合法引用、全量映射、Others 互斥、每 Stage 40 词样本及六份生成产物的逐字节可复现性。

未冻结词库草稿可在指定目录预览，不改正式资源：

```powershell
python tools/build_word_tags.py --preview .gradle/vocabulary-v2/tag-preview --source .gradle/vocabulary-v2/candidate-wordlist.csv
```

CSV 和审阅 JSON 使用 LF 换行。保留全部已有标签 ID；更新显示名称或规则时，同步检查词条语义及样本。改变词库内容后不能只刷新哈希跳过内容复核。

本标签分工执行的是数据与静态结构检查，未新增测试代码，未运行应用构建、安装或界面验收；整个改版的其他验证记录由版本日志和开发文档分别记录。

安全自查：只写本地标签资源、维护工具和审阅资料，未新增网络入口、运行依赖、权限或敏感日志；标签生成前后 CSV 字节哈希保持一致。
