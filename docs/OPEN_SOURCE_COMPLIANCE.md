## 分发范围

- MIT 覆盖项目有权许可的自有源代码、工具代码及项目说明文档。第三方代码即使嵌入这些目录，仍须保留自身许可。
- `wordlist*.csv`、`tools/` 内教学数据／摘录／作者稿／译稿及其派生产物不统一纳入 MIT。可确认的 CC-CEDICT 改编继续按 CC BY-SA 4.0；不明确部分在授权核实前不公开。
- `core/data/src/main/assets/demo/` 和 `wordlist-strokes/` 的笔顺轮廓／中线遵守 Arphic Public License；词库许可文本、元数据与字形分别解释。
- 不因新增项目 MIT 文件而将其他资源改标 MIT；第三方资源沿用各自声明。
- 公开源码与公开 APK 都要审核。APK 不包含作者稿，并不免除其内含图片、词库与字形的分发义务；公开源码也包括历史数据文件及 Git 可访问对象。

## 发布前操作清单

1. 固定拟发布 commit、源码包文件列表和 APK 哈希。区分待公开内容与留在本机的研究／备份材料。
2. 处理上表阻塞项，留存来源 URL、固定版本、作者、完整许可、授权范围、修改说明和处理证据。替换词库时保留 ID／引用契约。
3. 对本次公开范围执行逐文件审查，包括 `wordlist.original.csv`、`tools/wordlist_refined/baseline.csv`、`tools/wordlist_rebuild/baseline.csv`、摘录、机器译稿、图片、`.codex-remote-attachments/`、APK 与截图。`.gitignore` 不能撤销已有跟踪或远端可见内容。
4. 核对所有拟公开分支、标签和可访问历史。若未公开，可在独立审阅的发布目录／新仓库准备只含已获授权文件的版本；不能把仍含受限资源的工作区直接打 ZIP。若已经公开，停止继续分发问题资产，另行安排清理和通知；重写历史、删除远端、撤包不在本次文档任务内自动执行。
5. 按准确构建目标整理直接及传递依赖的 LICENSE／NOTICE；清查凭据、签名材料、个人路径和用户数据。核对 Git 文件名与扫描统计，避免在公开报告中暴露秘密。
6. 为已获授权的数据提供完整署名、许可及派生资源获取方式。检查 APK 的 Sources & licenses 内容、离线可读性和所需数据许可文本；需要界面调整时单独实施。
7. 对处理后的代码／数据按项目规则执行适当检查；以该发布版本实际验证结果替换旧证据。版权检查、结构校验、构建、安装和行为验收分别记录。
8. 发布说明写明版本、数据修改、许可边界和已解决项。版权异议可由权利人在项目托管平台提交 Issue；明确内容位置、主张及证明，维护者核对后暂停相关分发并处理，避免公开个人证件。

不把免责条款作为上述步骤的替代。本次不重写 Git 历史、删除头像、改写既有词库内容、打包或安装设备；源码整理、已有检查及提交推送结果见根目录 VERSIONLOG.md。
