## App 资源与链路

```powershell
python -B tools/build_chinese_resources.py --prepare
python -B tools/build_chinese_resources.py --build
python -B tools/build_chinese_resources.py --check
```

`--prepare` 下载固定资源到项目缓存，再通过 `prepare_melo_duration.py` 为已有 `/Ceil_output_0` 张量增加图输出声明；该固定模型适配器仅用 Python 标准库，不运行推理、不改算子或权重。派生 `model-duration.onnx` 为 170,429,590 字节，SHA-256 `c6029f601d660bd8ab720d1b6a159638c7613d9e4cbc4bd06f347c372205de55`，比原文件增加 40 字节，清单见 `tools/melo_resources/duration-export.json`。

`--build` 使用已有受校验的本机 Python 包生成 `chinese-speech` 音素／调值分片、来源与许可；`--check` 仅使用 Python 标准库，离线核对当前 CSV、全量词语／例句／写字请求、分片、23 条 PCM、许可哈希、覆盖统计及 200 MB 资源上限。CI 只执行固定资源准备与 `--check`，不需要外部试听实验或 Windows Python 原生库。

当前正式资源共 49,806 个读音键（包含写字），49,677 个支持，129 个不能可靠转换并保留系统回退说明。分片、短词 PCM 与派生模型合计 191,591,043 字节，约 191.6 MB。该覆盖是静态发音转换证据，不是全库声音或语言认证。

原模型和派生模型分别保留在 `.gradle/melo-resource-source/model.onnx` 与 `model-duration.onnx`，不将大文件入库。Gradle 在 asset 合并前检查派生模型固定体积与 SHA-256，只复制派生模型至忽略的生成资源；同一生成目录中的旧 `model.onnx` 会移除，避免双份打包。缺少模型必须先准备，不静默构建一个缺少内置模型的包。app 与媒体模块均将 `chinese-speech/model-duration.onnx` 精确声明为不压缩，运行时用 APK asset 文件描述符只读映射创建 ORT session，不向 App 缓存复制中文模型。后续 1.5.2 Debug 已核对派生模型 ZIP_STORED 与固定哈希、23 条 PCM 哈希，并安装启动；手机试听仍由用户验收，结果见版本日志。

`SpeechRequest.chinesePronunciation` 携带与中文原文绑定的拼音／例句分块，双语展开只保留匹配的中文 hint。写字单字按当前位置取主词音节；英语目标答题前仍不提供隐藏中文答案。查找键包含汉字、拼音和分块边界，区分同形异音。

默认词库使用构建期完整前端的音素／调值分片；新导入内容使用 Android 内置的有界拼音解析和保守变调。无法唯一对齐、未知音素或三声长串词界不明确时整条回退，不漏掉一部分后冒充成功。所有路径都先保留首尾边界，再一次 `add_blank`；长句保持 `speed=0.7`、`length_scale=1/0.7` 及完整波形。

播放器沿用原来的焦点、等待真正播放完成、双语顺序与 30 秒请求截止。每次中文原生推理使用独立取消对象；快速切卡或进入后台取消不会回退重播。上下文与失败重试不向播放器发出音频，仅最终目标字进入原有 PCM 播放／缓存链路；合成前失败或声学门槛不合格可使用已安装的离线系统语音，播放后失败不从头重复。缓存沿用媒体层有界内存及可调容量的持久 LRU，默认 256 MiB；本次不改数据库或学习记录。

## 统一单字与短词策略（2026-10-14）

按汉字、已解析音素和调值匹配 23 个已核听问题读法的固定样音，不仅按字形匹配；多音字与轻声互不借用。`short-words/index.json` 固定 SHA-256 为 `4746e4835f5ecf637b8bfe81228d5f208e1f82e0d75a16ebe28f941dd3795b44`。23 个 PCM16 单声道载荷合计 1,736,704 字节，来自用户选择的同声线样音，最终只做幅度匹配。来源索引在 `tools/melo_resources/short-words-source.json`，完整实验和用户反馈保留在项目外 `D:\AndroidStudioProjects\ttv-test`。

其余单字统一依次尝试：目标字重复三次并带逗号／句号，截取中间一次；若活动段 RMS 小于 −38 dBFS 或活动时长不足 80 ms，改为“请读，目标字，谢谢。”截中间；仍不合格则用“请读，目标字。”截末尾。最多三次推理，仍失败时沿用离线系统回退。目标音素与调值在上下文中保持原样，不重新套用承载句变调。

每次上下文请求模型原生音频和时长张量，逐项验证时长为非负整数、长度匹配输入、累计帧数乘 512 与音频长度一致；目标字包含两侧完整 blank，仅在两端做 3 ms 淡入淡出。这里的时长是模型分配，不是人工音素标注。单字资格由内容决定，包含合法单字分块，与首页、词条、写字等 scene 无关。

1–4 个纯汉字短词（多字例句分块除外）采用活动段电平校正：20 ms 帧、−55 dBFS 绝对门槛及距最强帧 −35 dB 相对门槛，目标 −22 dBFS，最大增益 +18 dB，sample peak 上限 0.79。这不是 true-peak 认证；未核听的极弱／过短输出不强行放大，单字进入上述重试。长句及英语继续用原电平。

短词使用新的 `render-short-v2` 指纹，包含样音索引和派生模型哈希，旧小声缓存不会命中新请求。长句保留原基础 manifest 指纹 `c36aace743eb21cc6017b624b3b972e6ee52c50e3fcb911be6e6085314d58256` 与 `render-v1`；英语 key 与原来一致。现有缓存无需全量清空。
